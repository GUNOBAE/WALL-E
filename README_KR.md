# WALL-E Robot Project

🌐 **언어:** [English](README.md) | **한국어**

<!-- 완성된 WALL-E 대표 사진 또는 GIF 추가 -->

홍익대학교 학생 5명이 함께 제작한 **WALL-E 로봇 프로젝트**입니다.

본 프로젝트는 **chillibasket의 오픈소스 WALL-E 프로젝트**를 기반으로 제작했으며, 원본 설계를 그대로 재현하는 것에 그치지 않고 실제 제작 과정에서 발생한 문제를 해결하기 위해 회로, 코드, 3D 모델을 일부 수정하고 새로운 부품을 추가했습니다.

팀은 미술·디자인 분야 학생 3명, 기계공학과 1명, 전자전기공학과 1명으로 구성되었습니다.

---

## 프로젝트 소개

이 프로젝트는 제가 처음으로 처음부터 끝까지 직접 참여한 개인 로봇 프로젝트에서 시작했습니다.

프로젝트를 시작하기 전까지는 전기전자, 프로그래밍, Arduino 등의 이론을 공부하는 데 많은 시간을 사용했지만, 실제로 무언가를 처음부터 설계하고 완성하는 경험은 부족했습니다.

그래서 WALL-E를 제작하는 것 자체보다도,

> **계획 → 설계 → 제작 → 실패 → 수정 → 완성**

이라는 프로젝트의 전체 과정을 직접 경험하는 것을 가장 큰 목표로 삼았습니다.

WALL-E는 이미 훌륭한 오픈소스 자료와 제작 사례가 존재했기 때문에 첫 프로젝트로 적합했고, 기존 프로젝트를 기반으로 하면서 필요한 부분을 직접 수정하고 개선하는 방식으로 진행했습니다.

---

## 주요 기능

완성된 WALL-E는 다음과 같은 기능을 갖습니다.

* Raspberry Pi 기반 웹 서버를 이용한 원격 조종
* 2개의 DC 모터를 이용한 주행
* Servo Motor Shield를 통한 7개의 서보 모터 제어

  * 머리
  * 목
  * 눈
  * 양팔
* OLED를 이용한 실시간 배터리 상태 표시

  * 현재 전압 (`V`)
  * 예상 배터리 잔량 (`%`)
* 배터리 저전압 경고
* USB-C를 이용한 내장형 배터리 충전
* 내부 전자부품 발열 관리를 위한 Cooling Fan
* 다양한 WALL-E Animation 및 동작 제어

# 주요 개선 사항

## 1. 실시간 배터리 상태 표시

원본 회로의 배터리 측정 기능이 사용한 하드웨어 환경에서 정상적으로 동작하지 않아 배터리 측정 회로를 별도로 구성했습니다.

브레드보드에서 먼저 테스트한 후 만능기판으로 제작했으며, OLED를 통해 다음 정보를 실시간으로 확인할 수 있도록 코드를 수정했습니다.

* 배터리 전압
* 예상 배터리 잔량
* 저전압 상태

이를 통해 WALL-E를 작동시키는 동안 현재 배터리 상태를 직관적으로 확인할 수 있습니다.

---

## 2. 내장형 USB-C 충전

기존에는 배터리를 충전하기 위해 내부에서 배터리를 분리해야 했습니다.

이를 개선하기 위해 **3S 배터리에 대응하는 USB-C 충전 모듈**을 내부에 추가했습니다.

본체 후면에는 USB-C 포트에 접근할 수 있는 구멍을 추가하여 WALL-E를 분해하지 않고도 충전할 수 있도록 했습니다.

> 충전 모듈을 사용할 경우 사용 중인 배터리의 셀 구성과 충전 전류에 맞는 제품을 사용해야 합니다.

---

## 3. 내부 Cooling Fan

Raspberry Pi, Buck Converter, USB-C 충전 모듈 등을 좁은 공간 안에 배치하면서 내부에 상당한 열이 축적되는 문제가 발생했습니다.

특히 Raspberry Pi와 충전 모듈의 발열이 컸기 때문에 Body Back을 수정하여 Cooling Fan을 추가했습니다.

Fan은 메인 전원 스위치와 연결되어 WALL-E의 전원을 켜면 함께 작동합니다.

---

## 4. Bracket Support

전자부품과 배터리를 모두 장착한 이후 WALL-E의 전체 무게가 증가하면서 하단 Bracket에 큰 하중이 집중되는 문제가 발생했습니다.

장기간 사용할 경우 해당 부분이 파손될 가능성이 있다고 판단하여 Body Bottom의 Bracket 결합부를 보강하는 **Bracket Support**를 새롭게 설계했습니다.

아치 형태의 구조물을 사용해 Bracket 주변의 하중을 분산하도록 설계했습니다.

---

## 5. Circuit Stand

WALL-E 내부 공간은 상당히 제한적입니다.

프로젝트 당시에는 많은 연결부에 납땜 대신 커넥터와 압착 단자를 사용했기 때문에 배선이 차지하는 부피도 예상보다 컸습니다.

이를 정리하기 위해 내부에 여러 층으로 구성된 **Circuit Stand**를 설계했습니다.

대략적으로 다음과 같이 부품을 배치했습니다.

```text
3층 : Servo Shield / Arduino
2층 : Raspberry Pi
1층 : Connector / Buck Converter / Power Circuit
```

각 층에는 배선을 통과시킬 수 있는 여러 개의 구멍을 만들어 내부 배선을 정리할 수 있도록 했습니다.

> 현재 다시 제작한다면 커넥터 사용을 줄이고 납땜과 열수축 튜브를 적극적으로 사용하여 내부 배선 부피를 줄이는 방향으로 설계할 것 같습니다.

---

## 6. OLED Frame Supporter

기존 OLED Frame은 OLED 모듈 자체를 단단히 고정해 주는 구조가 부족했습니다.

OLED를 보다 안정적으로 장착하기 위해 별도의 **OLED Frame Supporter**를 설계했습니다.

기존 OLED Frame에 Supporter를 접착한 후 OLED 모듈을 끼워 고정하는 방식입니다.

---

## 7. Track / Motor Bracket 개선

원본 Track의 일부 결합 구조는 PLA로 출력했을 때 장력이 부족하고 쉽게 파손되는 문제가 있었습니다.

따라서 Thingiverse 커뮤니티에서 공유된 **Pin 방식 Track Remix**를 사용했습니다.

Motor Bracket 역시 기존의 분리형 구조 대신 다른 제작자가 설계한 일체형 구조를 사용했습니다.

프로젝트에서는 원본 부품뿐만 아니라 여러 제작자의 Remix를 테스트하고, 실제 제작 환경에서 적합한 부품을 선택하여 사용했습니다.

---

## 8. WALL-E's House

Bracket Support를 추가한 이후에도 WALL-E의 전체 무게가 지속적으로 Bracket에 가해지는 것은 피할 수 없었습니다.

보관 및 이동 중 구조물에 가해지는 하중을 줄이기 위해 WALL-E 전용 보관 구조물인 **WALL-E's House**를 설계했습니다.

하우스가 WALL-E 하부 중심을 받쳐 무게를 분산시키도록 설계했으며,

* 장기 보관
* 전시
* 운반

시 Bracket에 걸리는 부담을 줄이는 역할을 합니다.

# Hardware

본 프로젝트에서는 다음과 같은 주요 부품을 사용했습니다.

| Category         | Component                     |
| ---------------- | ----------------------------- |
| Main Computer    | Raspberry Pi 3                |
| Controller       | Arduino                       |
| Battery          | 11.1V 3S Battery              |
| Servo Control    | 16 Channel Servo Motor Shield |
| Servo Motors     | 7 × SG90S                     |
| Drive            | 2 × DC Motor                  |
| Display          | OLED                          |
| Power Regulation | Buck Converter                |
| Charging         | USB-C 3S Charging Module      |
| Cooling          | DC Cooling Fan                |

배터리 전력은 크게 세 가지 계통으로 분배했습니다.

```text
11.1V 3S Battery
│
├── DC Motor Line
│     └── Drive Motors
│
├── 5V Controller Line
│     ├── Raspberry Pi
│     └── Arduino
│
└── 5V Servo / Auxiliary Line
      ├── Servo Motors
      ├── OLED
      └── Cooling Fan
```

프로젝트 당시 최대 부하를 기준으로 계산한 전체 피크 소비전류는 약 **7.43A**였습니다.

2.4Ah 배터리를 기준으로 한 단순 계산에서는 최대 부하 상태에서 약 19분의 동작 시간이 나오지만, 실제 사용에서는 모든 장치가 지속적으로 최대 부하로 작동하지 않아 약 **30~50분 정도** 사용할 수 있었습니다.

# Software

소프트웨어는 chillibasket의 기존 WALL-E 코드를 기반으로 수정했습니다.

### Original

[chillibasket/walle-replica](https://github.com/chillibasket/walle-replica)

기존 프로젝트에서 제공하는 다음 기능들을 기반으로 개발했습니다.

* Arduino 기반 Servo / Motor 제어
* Raspberry Pi 기반 Web Server
* Remote Control Interface
* WALL-E Animation

여기에 프로젝트에서 필요한 기능을 추가하거나 일부 코드를 수정했습니다.

주요 수정 사항은 다음과 같습니다.

* 실시간 배터리 전압 측정
* 배터리 잔량 계산
* OLED 출력
* 사용한 Pin Configuration에 맞춘 설정 변경
* Animation 수정 및 추가

Servo Motor는 실제 조립 전에 각각 Calibration을 진행했습니다.

최종 조립 이후에는 Servo Horn이나 Linkage에 접근하기 어렵기 때문에 **조립 전에 Calibration 값을 충분히 확인하는 것을 권장합니다.**

## ⚠️ STL Scaling 주의

일부 STL 파일은 Fusion 360에서 기존 Mesh 파일을 Solid로 변환하는 과정에서 실제 크기보다 약 **10배 크게 변환된 파일**이 있습니다.

해당 파일을 출력할 경우 슬라이서에서:

```text
Scale = 10%
```

로 변경한 후 출력해야 합니다.

긴 시간이 필요한 부품을 출력하기 전에는 반드시 모델의 실제 치수를 먼저 확인해 주세요.

# 제작 과정에서 발생한 문제와 배운 점

이 프로젝트에서 가장 많은 것을 배운 부분은 완성된 결과보다도 제작 과정에서 발생했던 여러 시행착오였습니다.

## 전류 용량을 고려한 전원 설계

초기에는 Buck Converter를 선정할 때 출력 전압을 맞추는 것에 집중했고, 필요한 최대 전류를 충분히 고려하지 않았습니다.

그 결과 전류가 부족해 3A 제품에서 5A 제품으로 변경해야 했고, 이후에는 각 부품의 최대 소비전류와 Servo Stall Current 등을 먼저 계산하는 방식으로 수정했습니다.

이 경험을 통해 전원부를 설계할 때는 단순히 전압만 맞추는 것이 아니라 **전체 부하와 최대 전류를 함께 고려해야 한다는 점**을 배웠습니다.

---

## Raspberry Pi ↔ Arduino 통신 노이즈

내부 공간을 줄이기 위해 Raspberry Pi와 Arduino 사이의 통신 케이블을 짧은 일반 배선으로 변경한 적이 있습니다.

하지만 변경 이후 통신 오류가 크게 증가했고, 기존 케이블을 사용했을 때 다시 정상적으로 통신했습니다.

작은 배선 변경도 신호 품질과 노이즈에 영향을 줄 수 있다는 점을 직접 경험할 수 있었습니다.

---

## 프로토타입의 중요성

프로젝트 초반에는 최종 크기의 부품을 바로 출력하여 조립했습니다.

하지만 이후 모델이 변경되거나 다른 Remix를 사용하면서 이미 출력하고 도색한 부품을 버리고 다시 제작해야 하는 경우가 생겼습니다.

다시 진행한다면 우선 축소 모델이나 최소한의 테스트 파트를 출력하여

* 부품 간 간섭
* 조립 가능 여부
* 배선 공간
* 센서 및 전자부품 위치

를 먼저 검증한 이후 최종 출력을 진행할 것입니다.

---

## 내부 배선

초기 프로젝트였기 때문에 납땜보다는 커넥터와 압착 단자를 많이 사용했습니다.

회로를 수정하기에는 편리했지만 최종 조립 단계에서 커넥터가 상당한 공간을 차지했습니다.

이를 통해 작은 로봇을 제작할 때는 회로 자체뿐만 아니라 **배선의 길이, 커넥터 크기, 유지보수성까지 기구 설계의 일부로 고려해야 한다는 것**을 배웠습니다.

---

## 부품 불량과 디버깅

제작 과정에서 Servo Shield, Charging Module 등 일부 전자부품의 불량으로 인해 상당한 시간을 디버깅에 사용하기도 했습니다.

처음에는 회로나 코드가 잘못되었다고 판단했지만, 여러 번 테스트한 결과 실제 부품 자체의 문제였던 경우도 있었습니다.

이 경험 이후에는 회로 전체를 한 번에 조립하기보다 각 모듈을 개별적으로 테스트한 후 통합하는 방식을 중요하게 생각하게 되었습니다.

# 프로젝트를 마치며

기술적으로 가장 복잡한 로봇을 만드는 것이 이 프로젝트의 목표는 아니었습니다.

이 프로젝트에서 가장 중요했던 것은 **직접 무언가를 처음부터 만들어 보는 경험**이었습니다.

처음에는 프로젝트를 시작하는 것 자체에 막연한 부담이 있었습니다. 이론을 공부하고 예제 코드를 따라 하는 것과, 아무것도 없는 상태에서 실제 결과물을 만드는 것은 완전히 다른 문제라고 느꼈기 때문입니다.

WALL-E를 제작하면서 회로 설계, 전원 구성, Raspberry Pi, Arduino, 3D 모델링, 3D 프린팅, 배선, 납땜, 조립, 디버깅 등 다양한 작업을 직접 경험했습니다.

그리고 무엇보다도 계획한 대로 되지 않는 수많은 문제를 하나씩 해결하면서 **프로젝트에 대한 막연한 두려움을 없앨 수 있었다는 점이 가장 큰 결과**라고 생각합니다.

이 프로젝트는 이후 진행하게 될 여러 로봇 프로젝트의 출발점이 되었습니다.

# Credits

이 프로젝트는 **chillibasket의 WALL-E 프로젝트**를 기반으로 제작되었습니다.

원본 프로젝트와 코드, 그리고 제작 가이드를 공개해주신 chillibasket에게 감사드립니다.

또한 프로젝트 제작 과정에서 Thingiverse 커뮤니티에서 공유된 여러 Remix 부품을 활용했습니다.

각 부품을 제작하고 공개해주신 모든 제작자분들에게 감사드립니다.

프로젝트를 진행할 수 있도록 3D Printer 및 제작 환경을 지원해주신 **홍익대학교 Maker Space**와 **ATOM 동아리**, 그리고 제작 과정에서 도움을 주신 모든 분들께도 감사드립니다.
